# bluemap-rs

Rust drop-in replacement for BlueMap (Java Minecraft 3D web map). Read `docs/00-overview.md` first (design,
decisions); subsystem research is `docs/01`–`09`, later docs are numbered by topic.

## Rules

- **Drop-in beats clean**: upstream configs, paths, PRBM/PNG/JSON, rstate and SQL schema stay byte-compatible
  (`docs/00-overview.md` "Product goal"). Copy visual quirks; never copy robustness bugs (`docs/08-github-issues.md`).
- Library crates use typed errors (`thiserror`); `anyhow` only in binaries and `bm-golden`.
- Hot paths take `&mut Vec<u8>`/scratch buffers instead of returning fresh allocations (`*_into` naming).

## Crates

- `bm-compress` — storage and region-chunk codecs; gzip/zlib encode via libdeflate, decode via flate2
- `bm-format` — tile grid, digit-split paths, PRBM writer, `compact` = BMQ3, the optimized hires blob (docs/17)
- `bm-java` — bit-exact Java behaviour (`Random`, `String.hashCode`, `Math`, `TrigMath`, ImageIO PNG behind feature
  `png`: madler zlib via `libz-sys`, zlib-rs output differs)
- `bm-math` — BlueMap `util.math`; test data generated by real Java
- `bm-map` — lowres (LODs, `LowresStore`, memory budget and spills: docs/22), rstate, mask, `settings.json` and
  `markers.json` writers (Gson 2.8.9 byte-identical)
- `bm-render` — hires mesher; byte-identical to BlueMap on every golden fixture
- `bm-storage` — file and SQL (sqlx) storage; `format: compat|optimized` (rules in `format.rs`, bundles in
  `optimized/bundle`); `bluemap --convert-storage <id> --to <format>`
- `bm-config` — HOCON parser (Configurate-compatible), typed configs, template generation
- `bm-web` — axum server: embedded BlueMap 5.29 webapp, map routes, live JSON + SSE; packed tiles for browsers running
  `client/unpack.js`, `server-unpack` for the rest (docs/18)
- `bm-wasm` — the BMQ3 unpacker behind that script; build checked in as `crates/bm-web/client/unpack.wasm`
- `bm-engine` — render pipeline (`Service`, `MapContext`, `update_map`), persistence thread, `-u` queue and watcher
- `bm-cli` — `bluemap` binary (BlueMapCLI flags, exit codes, log format); hidden `--plugin-ipc` = plugin core
  (`src/plugin/`, spec `commands.json`); musl: tuned mimalloc (`alloc.rs`), own `memset` (`memfns.rs`, docs/23)
- `bm-ipc` — shim↔core wire protocol; crate docs are the canonical spec
- `bm-golden` — test oracle: PRBM parser, `diff-render`, `compare-webroots`
- `platforms/` — Gradle (JDK 25): `common` shim (Java 21, BlueMapAPI 2.8.2 proxy), `paper`, `fabric` (docs/16),
  `docker`; jars bundle cores from `platforms/natives/<target>/`, version `5.29+rs.<crate>`
- Beyond parity (pauses, `memory-limit`, container auto-limit, MSPT): docs/15, `crates/bm-cli/src/throttle/`

## Commands

- Test: `cargo test --workspace` (background; first build compiles zstd's C). Iterate on `--release` tests with
  `--profile fast`; benches and acceptance stay `--release`.
- Testbox: `py -3 tools/testbox.py run <name> --sync [--lock] [--detach] -- <cmd>`, re-attach `wait <name>`;
  `stage <name>` once per checkout/reboot puts fixtures on tmpfs. `BM_TESTBOX=devbox` targets the devbox (faster,
  NVMe, shared: run timed work under `flock ~/bench.lock`).
- Merge gates (~8 min, fmt + x86/aarch64 clippy + tests + oracles + acceptance): `py -3 tools/testbox.py run <name>
  --sync -- python3 tools/gates.py [gate …]`
- Oracles: `cargo test -p bm-render --release`; `-p bm-map -- --ignored`;
  `-p bm-storage --release --test oracle_optimized -- --ignored`; `-p bm-web --test conformance -- --ignored`
- Golden renders (Java 5.29, MC 26.3): `py -3 tools/render_golden.py [fx…]` → `work/bluemap/<fx>/web`; diff:
  `cargo run -p bm-golden -- diff-render <golden> <candidate>`; re-render with ours: `-p bm-render --example render_map`
- Acceptance vs Java: `tools/accept.py` (`--watch <fx>` for `-u`), `accept_optimized.py`, `accept_versions.py [mc…]`,
  `accept_sql.py` (DBs: `tools/dbs.py start|stop|status`; remote tests need `BM_TEST_MYSQL_URL`/`BM_TEST_POSTGRES_URL`)
- e2e: `tools/e2e_paper.py`, `tools/e2e_fabric.py` (`--core BIN`, `--jar JAR`, `--server folia`, `--mc 26.2`,
  `--jvm=<flags>`)
- Bench: `tools/bench.py <label> -n 3 -- <cmd>`; Java vs ours `tools/bench_render.py`; real 4096² world
  `tools/real_world.py gen|edit|render|update|compare` (docs/14); serving harnesses in `docs/perf-exp/`
- After changing `bm_format::compact`'s decoder or `bm-wasm`: `py -3 tools/build_wasm.py` (needs clang + llvm-ar for
  wasm32: run it on the devbox), then
  `node tools/check_client_unpack.mjs <server> <compat webroot>` and `check_client_unpack_browser.mjs <map url> <chrome>`
- Release: `tools/build_core.py [targets…] [--jars]` (as CI); notices `tools/notices.py` (update
  `licenses/BUNDLED.txt` when bundled webapp/jars/C libs change). A `v*` tag makes a **draft** release: publish it,
  which triggers Modrinth/Hangar (`docs/release-publishing.md`). Image smoke test: `docker-smoke.yml`.
- Hung command: `py -3 tools/hangdump.py <pid>` (minidump with stacks)

## Agents

- In a worktree, every path you read, write or build is under that worktree. Only `work/` (junction) is shared.
- Never search from `C:/Users/hexay` or a drive root; Java/BlueMap sources are under `work/` and `../bluemap_reverse`.
- Local background shells are killed without notice when this machine runs low on memory. For remote jobs use
  `testbox.py run --detach` + `wait`, and re-check state with one command rather than trusting a silent wait.
- Commit with explicit paths, never `-am`: other sessions edit the same checkout.
- One feature per session.

## Gotchas

- `work/downloads` is a junction to `bluemap_reverse/work/downloads`. Before deleting a worktree or `work/` dir,
  unlink junctions with `cmd /c rmdir <link>`; a recursive delete follows them and wipes the shared downloads.
- Run `bluemap`/Java with cwd = the folder holding `config/` (paths are relative; fixtures: `work/bluemap/<fx>`).
- Unlit chunks render dark or are skipped: worlds written without light need `render_serve.py --relight`.
- Cross-builds need zig 0.16 (CI pin `ziglang==0.16.0`; testbox `~/.local/zigenv-016/bin`): libdeflate's AVX-512
  kernel needs `-mevex512` (set in `tools/build_core.py`) and zig 0.17 rejects that flag.
- `diff-render --inset 16` only when the two renders read different worlds (sky light leaks 15 blocks at world edges).
